Windows 编码兼容性实测

同样写 UTF-8，
为什么 JSON 会读失败？

在 Windows PowerShell 5.1 中，Set-Content -Encoding utf8 会在文件开头写入 BOM。Python 用 utf-8 文本模式读取后，json.load 遇到这个标记会报错。相同命令在本次测试的 PowerShell 7.6.9 中生成了无 BOM 的文件，读取成功。

2026 年 11 月 20 日实测　·　Windows　·　CPython 3.14.2

两个文件开头的字节

Windows PowerShell 5.1

EF BB BF 7B

前三个字节是 UTF-8 BOM，第四个字节才是左花括号。

PowerShell 7.6.9

7B 22 6F 6B

文件直接以左花括号开头，后面是 JSON 键名。

六组读取结果

在两个 shell 中分别执行同一条命令，写入一份新文件。随后分别用三种方式在 Python 中打开文件并交给 json.load。

Set-Content -LiteralPath sample.json -Encoding utf8 -NoNewline -Value '{"ok":true}'
读取同一段 JSON 的结果
Python 打开方式PowerShell 5.1 写入PowerShell 7.6.9 写入
encoding="utf-8"解析失败成功
encoding="utf-8-sig"成功成功
mode="rb"成功成功

失败组合返回 JSONDecodeError: Unexpected UTF-8 BOM。如果输入可能来自上述两种 shell，以下文本读取方式能处理本例中的两份文件。

import json

with open("sample.json", encoding="utf-8-sig") as stream:
    data = json.load(stream)

复现与来源

在同时安装了 Windows PowerShell 和 PowerShell 7 的 Windows 环境运行 python reproduce.py。脚本在临时目录中创建样本，输出版本、完整十六进制字节和各次读取结果。本次 5.1 的完整版本为 5.1.26100.9818。其他写入命令及默认编码需单独验证。
